# Complete edge reconstruction: later validation addendum

On 31 October 2026, all 1,929 non-bypass edge enclosures were reconstructed from scratch using the mathematical functions published with PR #2 at commit `2967dcb90849285447286f5a9aae5c66817b2078`. All integer midpoint vectors, common radii, binary exponents and precisions matched the saved data, and all 1,929 strict sign inequalities were rechecked. A separately reviewed coverage checker was independently rerun and confirmed the exact eight-panel coverage.

This supersedes the earlier validation-history statements that only one representative enclosure had been regenerated. The original manuscript, mathematical source, data and historical validation records are unchanged. It does not constitute human peer review, proof-assistant formalization or a novelty assessment.

## What actually ran

The run used a separately reviewed resumable orchestration wrapper around the **unchanged published functions**, not the literal `python edge/regenerate.py --full` command. Two processes handled disjoint panel queues `[0,2,4,6]` and `[1,3,5,7]`. Each panel began with newly generated shared coefficients. There were no restarts, and no result or shared checkpoint from the earlier representative-node test was reused.

For every panel `p`, the wrapper performed the following operations:

1. Authenticate the published code, node table and compressed input files. Set the exact released `python-flint==0.9.0` backend, checking its binary against the official wheel.
2. Load panel midpoint `c`, half-width `h`, harmonic-node endpoints and every non-bypass saved record.
3. Call the published `generation(p, 600, 360, 2048, c, h)` once to construct fresh shared coefficient jets.
4. For every saved record `r` in that panel, call the published `evaluate(shared, r, c, h, left_endpoint, right_endpoint)`. Compare the entire resulting record to the saved midpoint list, radius, exponent and precision, without floating-point tolerances.
5. Call the published `verify(r, u_endpoints, nodes)` to recheck the strict Bernstein/error-budget inequality. Save a per-case result only after both exact comparison and strict sign verification succeed.
6. Require the exact ordered set of panel cases. The per-panel counts were `246,245,243,241,240,239,238,237`, totaling 1,929.

The wrapper provided atomic progress records and optional resumption; the completed run did not exercise resumption. Those scheduling/checkpoint facilities changed no mathematical operation. The aggregate receipt pins the wrapper, coverage checker, published mathematical source, input manifest, official wheel and loaded backend hashes.

## Independent coverage and canonical comparison

The coverage checker verified checkpoint identities, all per-case records, uniqueness and exact membership. The 1,929 reconstructed cases and 63 disjoint previously certified bypass boxes equal all `8 × 249 = 1,992` required panel/node pairs. The 63 bypass inequalities had already passed exact identical-code replay; they are not represented as coefficient enclosures regenerated by this run.

For each matched jet, canonical JSON is formed from `{m, rad, e, p}` using sorted keys and separators `(',', ':')`, then hashed with SHA256. The list of `{panel, node, matched_jet_sha256}` records is sorted by panel and node, encoded the same way, and hashed. The complete matched-jet digest is:

`22c038b14345430607d71e0eb7e599dd06338b2a453419d8d0b8fe15ade8904c`

Both queues exited 0. Their summed per-panel elapsed times were approximately 803.38 and 807.98 seconds; the largest recorded per-process peak resident set was 274,280 KiB. Timing and memory are observations of this run, not guarantees for another environment.
